The test expects BACKSLASH escaping (\") but PowerShell uses BACKTICK
escaping (`"). The code is CORRECT, the test assertion is WRONG.

DOCUMENTED FIX HISTORY
----------------------

Function: Register-ContextMenu

Fix Applied:
```powershell
# BEFORE (WRONG):
$escapedPath = $ExePath -replace '"', '\"'  # Backslash escape doesn't work in PowerShell

# AFTER (CORRECT):
$escapedPath = $ExePath -replace '"', '`"'  # Backtick escape
```

WHY TEST STILL FAILS
--------------------
The regex '[^\\]"[^\\]' looks for:
  - Character that is NOT a backslash
  - Followed by a quote
  - Followed by another character that is NOT a backslash

Example: Test path "C:\Program Files\Test`"App\DailyMotivation.exe"
  - The sequence `"A matches the regex
  - Backtick is not a backslash → matches [^\\]
  - Quote follows
  - Letter 'A' is not a backslash → matches [^\\]

THE TEST IS CHECKING FOR THE WRONG ESCAPE MECHANISM

PowerShell Escaping Works Differently:
  1. In source code: `" is interpreted as escaped quote
  2. When written to registry: becomes literal quote character in value
  3. Windows reads registry value with outer quotes as delimiters
  4. Inner quote in path is just a filename character

SECURITY ANALYSIS
-----------------
The current implementation IS SECURE. No command injection is possible because:
  - Entire path is wrapped in outer quotes: "...path..." /setfolder "%1"
  - Inner quote in filename does not break out of quoted string
  - Windows Explorer interprets outer quotes correctly

REQUIRED FIX
------------
File: Tests/Unit/Security.Tests.ps1
Line: 79

Option A - Fix the regex to accept backtick escaping:
```powershell
# Current (WRONG):

# Fixed:

```
