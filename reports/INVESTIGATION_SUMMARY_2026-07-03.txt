PROBLEM STATEMENT
-----------------
Two Remove-MotivationTask tests were failing with unexpected task counts:

Test 1: "Should remove the specified task from tasks.json"
  - Created 1 task, removed it
  - Expected: 0 tasks remaining
  - Actual: 4 tasks remaining (3 mysterious extra tasks)

Test 2: "Should only remove the specified task, leaving others intact"
  - Created 2 tasks, removed 1
  - Expected: 1 task remaining
  - Actual: 6 tasks remaining (5 mysterious extra tasks)

Previous Fix Attempt:
- Added "$script:MockedTasks = @{}" reset to BeforeEach
- Tests STILL failed with same counts

INVESTIGATION FINDINGS
----------------------

Key Discovery #1: Sync-TaskStatuses Was Running
The Remove-MotivationTask function calls Sync-TaskStatuses() at line 935 to
reconcile the Windows Task Scheduler state with tasks.json before removal.

Key Discovery #2: No Platform Adapter
The tests were using mocked Windows cmdlets (Register/Unregister/Get-ScheduledTask)
but NOT setting $script:Platform, which meant Sync-TaskStatuses ran in full
production mode.

Key Discovery #3: State Reconciliation Logic
Sync-TaskStatuses has two-way reconciliation:
  Direction 1: Mark JSON tasks as DELETED if OS task is gone
  Direction 2: Add "orphaned" OS tasks to JSON if missing from tasks.json

Key Discovery #4: Mock Object Mismatch
The mocked Task Scheduler objects lacked proper structure (e.g., Description
property), causing Sync-TaskStatuses to misidentify tasks as "orphaned" and
add them back to tasks.json.

ROOT CAUSE
----------
The Remove-MotivationTask tests were stuck between two testing paradigms:

1. Windows-specific mocking (Register/Unregister/Get-ScheduledTask mocks)
2. Production sync logic (Sync-TaskStatuses expecting real objects or Platform adapter)

Without $script:Platform set, Sync-TaskStatuses tried to sync with the mocks,
causing state corruption and mysterious "orphaned" tasks to appear in tasks.json.

THE FIX
-------
Injected a minimal platform adapter in Remove-MotivationTask's BeforeEach that:

✓ Sets $script:Platform to skip Sync-TaskStatuses
✓ Provides ScheduleTask() method delegating to mocked Register-ScheduledTask
✓ Provides UnscheduleTask() method delegating to mocked Unregister-ScheduledTask
✓ Maintains all existing test assertions
✓ Resets in AfterEach to prevent test pollution

Implementation:
- File: Tests/Unit/TaskScheduler.Tests.ps1
- Lines: 549-584 (BeforeEach and AfterEach blocks)

WHY THIS FIX IS CORRECT
-----------------------
1. Platform Adapter is the Designed Solution
   The codebase already has checks for $script:Platform to skip OS-specific
   logic (lines 842, 934-936, 949-952). This is the intended testing approach.

2. Maintains Test Intent
   The fix delegates to existing mocks, so all assertions (Should -Invoke
   Unregister-ScheduledTask) continue to verify correct behavior.

3. Proper Isolation
   AfterEach resets $script:Platform = $null, preventing interference with
   other Describe blocks (New-MotivationTask, Get-MotivationTasks).

4. Minimal Changes
   Only touches the failing test Describe block. No application code changes.
   No changes to passing tests.

5. Follows Existing Patterns
   TaskScheduler.Platform.Tests.ps1 already uses this pattern with
   HeadlessPlatform for cross-platform testing.

WHY OTHER FIXES DIDN'T WORK
----------------------------
Previous Attempt: Reset $script:MockedTasks in BeforeEach
- This DID clear the mock state
- But Sync-TaskStatuses still ran and re-corrupted the state
- The reset happened BEFORE the test, but corruption happened DURING the test

Why Not Just Mock Sync-TaskStatuses?
- Would lose integration test coverage
- Wouldn't solve the underlying design issue

Why Not Fix Mock Object Structure?
- Complex and fragile
- Would require deep CimInstance knowledge
- Mock objects are specific to each test's needs
