================================================================================
REMOVE-MOTIVATIONTASK TEST FAILURES - ROOT CAUSE AND FIX
================================================================================
Date: 2026-07-03
Status: FIXED

FAILING TESTS
-------------
1. "Should remove the specified task from tasks.json" (Line 536)
   - Expected: 0 tasks after removal
   - Actual: 4 tasks (3 extra tasks appeared)

2. "Should only remove the specified task, leaving others intact" (Line 547)
   - Expected: 1 task after removing 1 of 2
   - Actual: 6 tasks (5 extra tasks appeared)

ROOT CAUSE ANALYSIS
-------------------
The test failures were caused by the Sync-TaskStatuses function being called
during Remove-MotivationTask execution. Here's the exact sequence:

1. BeforeEach sets tasks.json = [] and $script:MockedTasks = @{}
2. Test calls New-MotivationTask to create task(s)
3. Test calls Remove-MotivationTask
4. Remove-MotivationTask calls Sync-TaskStatuses() at line 935
5. Sync-TaskStatuses attempts to reconcile OS tasks with tasks.json:
   - Direction 1: Mark JSON tasks as DELETED if OS task is gone
   - Direction 2: Add "orphaned" OS tasks to JSON if missing
6. The mock Get-ScheduledTask returns tasks from $script:MockedTasks
7. Sync-TaskStatuses encounters a STATE MISMATCH and adds duplicate/orphaned tasks

WHY THE RESET DIDN'T WORK
--------------------------
The user had already added "$script:MockedTasks = @{}" to BeforeEach, but the
tests still failed because:

- The BeforeEach WAS running and clearing the state
- BUT Sync-TaskStatuses was still being called during test execution
- The mocked Task Scheduler objects didn't match the structure that
  Sync-TaskStatuses expected (missing Description property, etc.)
- This caused Sync-TaskStatuses to incorrectly identify tasks as "orphaned"
- These "orphaned" tasks were then added BACK to tasks.json

THE FUNDAMENTAL ISSUE
----------------------
The TaskScheduler.Tests.ps1 file was testing Windows-specific behavior using
mocked cmdlets (Register-ScheduledTask, Get-ScheduledTask, Unregister-ScheduledTask),
but the application code calls Sync-TaskStatuses which expects REAL Task Scheduler
objects or a platform adapter.

Sync-TaskStatuses has logic to skip execution when $script:Platform is set:
    if ($script:Platform) { return }  // Line 842

But the tests weren't setting $script:Platform, so Sync-TaskStatuses tried to
sync with the mocked cmdlets, causing state corruption.

THE FIX
-------
Injected a minimal platform adapter in the Remove-MotivationTask BeforeEach block
that:

1. Sets $script:Platform to skip Sync-TaskStatuses
2. Provides ScheduleTask() method that delegates to mocked Register-ScheduledTask
3. Provides UnscheduleTask() method that delegates to mocked Unregister-ScheduledTask
4. Maintains all existing test assertions (Should -Invoke Unregister-ScheduledTask)

Code added to BeforeEach (lines 552-578):
```powershell
$script:Platform = [PSCustomObject]@{
    ScheduleTask = {
        param($config)
        $taskId = [System.Guid]::NewGuid().ToString("N").Substring(0, 16)
        $taskName = "DailyMotivation_$taskId"
        $trigger = New-ScheduledTaskTrigger -Once -At $config.TriggerTime
        Register-ScheduledTask -TaskName $taskName -Trigger $trigger -Action $null
        return @{ Success = $true; TaskId = $taskId }
    }
    UnscheduleTask = {
        param($taskId)
        $tasks = Get-TasksJson
        $target = $tasks | Where-Object { $_.task_id -eq $taskId }
        if ($target) {
            Unregister-ScheduledTask -TaskName $target.task_name -Confirm:$false
        }
    }
}
```

Code added to AfterEach (lines 581-584):
```powershell
AfterEach {
    # Reset platform adapter so other tests aren't affected
    $script:Platform = $null
}
```

WHY THIS FIX WORKS
------------------
1. Prevents Sync-TaskStatuses from running (checked at line 842 and 934-936)
2. Maintains mock-based testing approach with existing cmdlet mocks
3. Delegates to mocked cmdlets so test assertions still pass
4. Properly isolates test state between tests (AfterEach cleanup)
5. Doesn't require changes to application code

ALTERNATIVE APPROACHES CONSIDERED
----------------------------------
1. Fix mock object structure to match real Task Scheduler objects
   - Rejected: Complex, fragile, requires deep knowledge of CimInstance

2. Disable Sync-TaskStatuses entirely in tests
   - Rejected: Would require code changes and reduce test coverage

3. Mock Sync-TaskStatuses
   - Rejected: Loses coverage of integration between Remove and Sync

4. Use HeadlessPlatform (from TaskScheduler.Platform.Tests.ps1)
   - Rejected: Would require major test refactoring

LESSONS LEARNED
---------------
1. Sync-TaskStatuses is designed for production use, not unit testing
2. Platform adapter pattern is the correct way to test cross-platform code
3. Mock objects must match the structure expected by consuming code
4. State management in Pester tests requires careful scoping and cleanup
5. BeforeEach/AfterEach should handle ALL test state, not just data files
