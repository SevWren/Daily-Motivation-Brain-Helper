## Root Cause of Current Bug

**Symptom:** "Access is denied" error when scheduling a task via the UI.

**Root cause:** Commit `6378e54` deleted the following block while stripping bug-reference comments:

```powershell
$script:ConfigDefaults = [PSCustomObject]@{
    default_trigger_hour   = 14
    task_warning_threshold = 5
}
```

This object is the fallback used in three places where `$cfg.default_trigger_hour` may be absent:

- `DailyMotivation.ps1:981` — `Get-ScheduleTime` (first definition)
- `DailyMotivation.ps1:1855` — `Get-ScheduleTime` (duplicate/overload)
- `DailyMotivation.ps1:2979` — `scheduleBtn` click handler

When the variable is undefined (`$null`), `$script:ConfigDefaults.default_trigger_hour` evaluates to `$null`, and `[int]$null = 0`. A trigger hour of `0` (midnight) may pass local validation but causes Task Scheduler to reject the registration with "Access is denied" in restricted user contexts.
